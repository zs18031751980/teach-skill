可以用字典记录已经访问过的数及其下标，一次遍历寻找答案。返回的下标从 0 开始；数值可以相同，但下标必须不同。

对当前数 `x`，我们需要的另一个数是 `target - x`，称为补数。逐对尝试需要枚举至多约 `n²/2` 对元素；用字典保存已访问的数，就可以直接查找补数是否出现过。

遍历时，字典 `seen` 的键是数值，值是该数值此前出现的一个下标。每一步先查询补数：若存在，就返回它的下标与当前下标；否则，再将当前数及下标存入字典。

**先查找、后存入**是保证下标不同的关键。查询时字典里只有之前的元素，不会把当前元素与自身配对。

```python
def two_sum(nums, target):
    seen = {}

    for i, x in enumerate(nums):
        complement = target - x
        if complement in seen:
            return [seen[complement], i]

        # 查询之后才记录当前元素，避免复用同一下标。
        seen[x] = i

    return []
```

例如 `nums = [3, 3]`、`target = 6`：访问下标 `0` 时，补数 `3` 还不在字典中，于是存入 `{3: 0}`；访问下标 `1` 时，找到之前的 `3`，返回 `[0, 1]`。若输入只有 `[3]`，则循环结束后返回 `[]`，不会返回 `[0, 0]`。空数组、只有一个元素或其他无解输入同样返回 `[]`。

为什么不会漏掉答案？在每次查询前，字典保存了此前出现过的每种数值的一个下标。如果一组解位于 `j < i`，遍历到 `i` 时，`nums[j] = target - nums[i]` 必定已经在字典中，因此可以找到一组解。重复数值即使覆盖了旧下标，留下的下标仍然早于 `i`，且数值相同，不影响找到合法答案。返回时两个数之和由补数关系保证等于 `target`；若遍历结束仍未找到，就不存在符合条件的下标对。多个解时，函数返回遍历中首先找到的一组。

设数组长度为 `n`，按整数算术、哈希和比较耗时为常数的通常分析口径：字典查询平均为 `O(1)`，插入平均摊还为 `O(1)`，因此算法平均时间复杂度为 **`O(n)`**；哈希冲突严重时，最坏时间复杂度可达 **`O(n²)`**。字典至多保存 `n` 个不同数值，额外空间复杂度为 **`O(n)`**。若整数位数随输入规模增长，还需计入大整数运算的代价。
