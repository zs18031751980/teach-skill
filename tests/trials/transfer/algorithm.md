S 到 T 的最短路径有 **2 条**，每条都是 3 条边：

- S → A → C → T
- S → B → C → T

不能因为 C 已经访问过就直接跳过，是因为**第一次到达 C 能确定最短距离，却不一定已经找齐到达 C 的所有最短路径**。

沿这张图走一遍，假设先处理 A、再处理 B。我们给每个点记两个数：`dist` 表示从 S 出发的最短距离，`ways` 表示目前累计找到的最短路径条数。

| 处理到哪里 | C 的距离与条数 | 为什么 |
|---|---|---|
| 从 S 发现 A、B | C 尚未发现 | 到 A、B 都是距离 1，各有 1 条路径 |
| 从 A 沿 A → C | `dist[C] = 2`，`ways[C] = 1` | 第一次发现 C，得到 S → A → C，并把 C 入队 |
| 从 B 沿 B → C | `dist[C] = 2`，`ways[C] = 2` | S → B → C 也是长度 2，新增了另一条同样短的路径 |

关键就在最后一行：经 B 到 C 的距离为 `dist[B] + 1 = 2`，恰好等于已知的 `dist[C]`。因此要把 `ways[B]` 加进 `ways[C]`。如果看到“C 已访问”就跳过，会漏掉 S → B → C，随后也就漏掉 S → B → C → T。

**这次只增加 C 的路径条数，不需要把 C 再入队。** 处理 A 后，队列中 B 排在 C 前面；所以 B 对 C 的条数贡献会在 C 出队前完成。等轮到 C 时，`ways[C]` 已经是 2。将这两条路径各接上 C → T，就得到 `dist[T] = 3`、`ways[T] = 2`。

因此，检查一条边 u → v 时，要区分三种情况：

- v 尚未发现：确定 `dist[v] = dist[u] + 1`，令 `ways[v] = ways[u]`，并将 v 入队。
- v 已发现，而且 `dist[u] + 1 == dist[v]`：找到另一批最短路径，累加 `ways[u]`，不用重复入队。
- `dist[u] + 1 > dist[v]`：这条路线更长，才直接忽略。

无权图的 BFS 按距离逐层处理，保证第一次发现时距离已经最短，也保证一个点出队前，上一层能到达它的点都已处理完。这样，节点只需入队一次，所有最短路径的条数仍能完整汇总。
