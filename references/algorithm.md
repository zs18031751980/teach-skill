# 算法题讲解模式

共同表达、检查和交付遵守主技能。本模式把方法选择与代码实现讲清楚，不将已有代码逐行解释模式自动叠加进来；用户要求逐行时再读取对应参考。

## 从题目条件到方法

明确输入、输出、范围与边界，从这些条件推导需要的时间和空间开销。解释关键数学性质、状态、不变量或数据结构为何能得到答案。

朴素方法可作为理解和正确性的参照；存在重复工作时说明实际优化来自哪里。不能把所有题都套成“找冗余—数据换时间”，也不虚构试错史、更多解法或未经证明的最优性。默认给足解决本题所需的方法；多解对照仅在用户要求或确能解释关键取舍时展开。

## 针对算法难点选讲法

只问算法概念或某个步骤时，聚焦该疑点，不强制提供整道题和完整代码。需要完整题解时才沿本文其余要求展开。

按下文“常见方法的讲解落点”选择本题相关内容；数学型算法给出实际推导，不为凑流程引入其他方法。

在关键节点展示数组、指针、队列或状态值的变化，解释每次更新改变了什么、保留了什么性质。规模小时可手推，变化复杂时才用表或图；不逐步打印大量重复状态。分析空间时区分输出空间、辅助结构和递归栈，说明采用的口径。

## 联系代码

按逻辑块解释变量、条件、循环和返回如何实现上述关系。关键索引、初始化、状态转移及异常/边界处理给出实际理由；不把每个判断都笼统写为“防越界”。需要的中间步骤不能省去。

给完整代码时使用题目指定语言和接口；在线评测的函数接口无需硬加输入程序，独立程序则补齐必要入口和输出。代码变量与讲解一致，注释用于解释关键选择，不逐句复述显然操作。

分析实际算法的时间与空间复杂度，区分平均、期望、摊还和最坏情况。不能用哈希查询平均 O(1) 推出无条件最坏线性；有必要时读取 `examples.md`。没有依据时不用“最优”标签。

## 正确性与交付

在主技能同次复核中确认方法与代码对应、边界、复杂度和样例。使用适当的论证说明为何正确，例子或反例测试不能替代普遍性证明。可以运行时验证代码；只能手算时如实区分，不声称运行通过。

正文按学习依赖组织题意、方法、实现、完整代码以及有教学价值的样例推演或正确性说明，标题和段落不固定。复杂度集中说清即可，不在多个小节重复。内部核验表不进入正文，样例里的数值变化正常展示。

## 常见方法的讲解落点

按用户实际卡点选择下列子主题。每段中的输入和数字均为教学条件；换到用户材料时重新核对，不能把示例答案直接套用。只输出当前问题所需的解释，不照搬本文件的备课结构。

### 二分查找 / 答案二分

卡点是“等于目标为什么仍向左”时，用 [1,2,2,4] 找首个 ≥2 的下标，答案为 1。采用半开区间时，命中中点只说明右边界可缩到这里，尚未排除更左的相等值；给出每次区间移动及退出位置含义。

若问答案二分，先定义真假判定并证明单调性；例如负载上限增大是否仍能使用原可行划分。不能仅因答案是整数就二分，不能将找任意匹配的退出规则套到边界查找。

### 双指针 / 滑动窗口

卡点是窗口为何能收缩时，明确依赖的单调性。找和至少为 3 的最短连续段，非负数时可按和判断扩张收缩；含负数的 [1,−1,3] 中，常见“满足才收缩、直到和不足就停”会记录长度 3 后停在 [−1,3]，漏掉长度 1 的 [3]。

若是有序数组两数和，按和过大或过小解释哪一端可安全排除；若是字符频次窗口，解释进入和离开怎样更新计数。不要把这些不同依据都压成“两个指针各走一遍”。

### 前缀和 / 差分

卡点是下标公式时，用 a=[2,−1,3]，定义 p[0]=0、p[i+1]=p[i]+a[i]，得到 p=[0,2,1,4]；半开区间 [1,3) 的和是 p[3]−p[1]=2。先固定区间含义，再解释相减取消了什么。

若问差分，说明闭区间 [l,r] 加 v 对应差分在 l 加 v、在 r+1 减 v（需要边界位置或单独处理），并用累积还原。查询与更新的方向不同，不只互换术语。

### 动态规划

卡点是状态或遍历方向时，让相同例子暴露依赖。只有一件重量 2、价值 3 的 0/1 物品，容量 4，定义 dp[c] 为容量不超过 c 的最大价值且初始全为 0；容量正序更新会用本轮刚得到的 dp[2]=3 算出 dp[4]=6，等于重复选物品，倒序则保持上一轮依赖。

若问初始化，用“恰好装满”与“容量不超过”对比不可达和零收益的区别；若问转移，逐项说明候选来源如何覆盖所有合法选择。不要先给公式再用变量名重复解释。

### 贪心

卡点是为什么局部选择安全时，用不重叠区间数量最大化：选结束最早的区间，可将某个最优解的第一个区间替换为它，不缩小留给后续的时间范围。说明交换后可行且数量不减，再联系实现。

若加入权重，换用区间 [0,2)、[2,4) 权重各 1，与 [0,4) 权重 10，最早结束策略的数量目标与总权重目标不再一致。重点是目标改变为何破坏原证明，不推广成贪心总不可靠。

### DFS / 回溯

卡点是“为什么递归返回后要撤销”，用从 [1,2] 生成排列：选择 1 后选择 2 得 [1,2]，返回时移除 2、再移除 1，另一分支才能从 2 开始得到 [2,1]。同时说明保存答案时是否需复制可变路径。

若任务是图的可达性，全局 visited 可避免重复探索；若枚举简单路径，访问标记可能需随路径撤销。根据输出目标决定状态生命周期，不用单一 visited 模板套所有 DFS。

### BFS / 最短路

卡点是带权图能否用普通 BFS 时，用 A→C 权重 10、A→B 权重 1、B→C 权重 1：边数最少是一条边，但最小总代价为 2。说明普通 BFS 按层处理的度量是什么。

若问 Dijkstra，围绕非负边权下为何能确定当前最小暂定距离展开；若有负权，原有确定逻辑不保证成立。若问代码中何时标记访问或跳过旧堆项，沿用实际实现解释，不混用不同版本的判据。

### 堆 / 单调结构

卡点是“堆为什么不是排好序的数组”，用 [1,3,2] 满足最小堆父不大于子的关系但不是升序排列，解释堆顶保证与整体顺序的区别。

若问单调栈求下一个更大元素，用 [2,1,3] 中 3 到来时依次为 1 和 2 确定答案；弹出是因为这些元素的问题已被当前元素解决。窗口最值队列可存下标判断过期；只存值的实现也可正确，但需保留重复值或等价计数，并结合移出窗口的值处理队首。用 [3,3,1]、窗口长 2 说明移走第一个 3 后仍须保留第二个 3，不能把一种实现要求当作唯一做法。

### 分治 / 递归

卡点是为何对半拆分仍非 O(log n)，用归并排序：每层子问题合并工作总计 O(n)，平衡拆分层数 O(log n)，所以总时间 O(n log n)。区分路径深度与整棵调用树的总工作。

若问递归为何不结束，检查实际输入是否朝基本情况推进；若问空间，区分递归栈、子数组复制和合并缓冲。不能只因代码有两个递归调用就断言指数复杂度。

## 用一个状态解释代码与证明

讲循环时可选关键一轮，说明进入时已知什么、本轮改变什么、离开时仍保证什么，最后连接终止状态与答案。这是推理方法，不要求把每次迭代写成固定三段。

例如在排序数组中寻找“第一个不小于 target 的位置”，采用半开区间 [left, right) 时，可围绕“left 左边已知小于 target，right 起右侧已知不小于 target”解释边界移动。用户若给定另一种实现，沿用它的区间定义，不强行换模板。

讲 DP 空间压缩时，以 0/1 选择中的依赖为例：若状态应读取上一轮结果，某种更新方向却读到了本轮刚更新的状态，就可能重复使用当前元素。解释应落到具体依赖和数组读写顺序，不能只让用户记“倒序遍历”。

## 复杂度与工程现实

嵌套循环不自动等于二次复杂度：看各指针或元素总共移动、入栈、出栈多少次。递归不仅计栈深，还要计节点总工作。库函数、切片、字符串拼接、排序及拷贝的成本若影响结论，应计入，不能隐藏在一行语法后面。

将渐近复杂度用于比较增长趋势；不能据此承诺某个输入规模一定在固定秒数内完成。数据范围、表示方式、语言运行时及实际环境影响运行时间，测量过才报告实测。

## 根据错误反馈继续讲

若出现反例，先定位破坏的是状态定义、判定条件、转移、边界还是实现映射，再解释最小修正为何有效；不直接贴另一套代码。若只是不理解，可缩小输入或改变呈现方式，不无故换算法。
