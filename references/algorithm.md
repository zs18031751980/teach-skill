# 算法题讲解模式

共同表达、检查和交付遵守主技能。本模式把方法选择与代码实现讲清楚，不将已有代码逐行解释模式自动叠加进来；用户要求逐行时再读取对应参考。

## 从题目条件到方法

明确输入、输出、范围与边界，从这些条件推导需要的时间和空间开销。解释关键数学性质、状态、不变量或数据结构为何能得到答案。

朴素方法可作为理解和正确性的参照；存在重复工作时说明实际优化来自哪里。不能把所有题都套成“找冗余—数据换时间”，也不虚构试错史、更多解法或未经证明的最优性。默认给足解决本题所需的方法；多解对照仅在用户要求或确能解释关键取舍时展开。

DP 说明状态含义、转移与初始条件；贪心说明选择为何安全；搜索说明状态空间、剪枝和终止；数学题给出真实推导。只展开所用方法，不为凑流程补不适用章节。

## 联系代码

按逻辑块解释变量、条件、循环和返回如何实现上述关系。关键索引、初始化、状态转移及异常/边界处理给出实际理由；不把每个判断都笼统写为“防越界”。需要的中间步骤不能省去。

给完整代码时使用题目指定语言和接口；在线评测的函数接口无需硬加输入程序，独立程序则补齐必要入口和输出。代码变量与讲解一致，注释用于解释关键选择，不逐句复述显然操作。

分析实际算法的时间与空间复杂度，区分平均、期望、摊还和最坏情况。不能用哈希查询平均 O(1) 推出无条件最坏线性；有必要时读取 `examples.md`。没有依据时不用“最优”标签。

## 正确性与交付

在主技能同次复核中确认方法与代码对应、边界、复杂度和样例。使用适当的论证说明为何正确，例子或反例测试不能替代普遍性证明。可以运行时验证代码；只能手算时如实区分，不声称运行通过。

正文按学习依赖组织题意、方法、实现、完整代码以及有教学价值的样例推演或正确性说明，标题和段落不固定。复杂度集中说清即可，不在多个小节重复。内部核验表不进入正文，样例里的数值变化正常展示。
