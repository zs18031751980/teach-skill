# 文件概括整合模式

共同表达、检查和交付遵守主技能。此模式按原文组织，不自动添加讲解模式的例子、比喻或外部背景。

## 范围与概括级别

采用用户指定范围和级别，未指定级别时采用 L2；仅当用途与默认方案存在实质冲突时澄清。各级没有字数比例或每段句数配额。

| 级别 | 信息处理方式 |
|------|----------------|
| L1 详细整合 | 接近完整原文，优化措辞和衔接，保留各论点、论据、数据和示例过程 |
| L2 适中概括 | 合并同主题相邻内容，去掉冗余措辞，保留全部独立信息、必要论证关系和例子含义 |
| L3 精简概括 | 压缩可重复推知的展开过程，以紧凑表达保留每个原句的独立信息及条件；有独立意义的步骤与例子不能消失 |
| L4 摘要式整合 | 按章节集中表述核心关系，将支撑信息凝练合并；仍保留每个原句不可由其他内容代替的信息，不承诺固定长度 |

所有级别保持原句信息覆盖。原文信息密集时，L3/L4 也可能较长。用户明确改为选取重点或限制范围时按新要求执行，不再声称全文逐句覆盖；严格长度与全文信息确实无法兼容时说明冲突，不擅自删信息。

## 读取与提取

先确定材料是否完整，再选环境可用的读取、提取或转换工具。不假定某个名为 `read` 的工具存在，也不因扩展名就断言无法处理。

- PDF：检查文本提取顺序、跨栏、表格和公式。扫描页按可用能力 OCR 并核对图像；提取不到不能当作空白页。
- Word：按原顺序读取段落和表格，留意页眉页脚、脚注、文本框及图片中的有效内容。只读取普通段落不足以代表全文。
- PPT：按幻灯片顺序读取标题、文本、表格及备注；图表、SmartArt、图片文字需补充查看，不将普通文本框提取结果当作全部内容。
- 旧格式：可用本地工具时转换后读取，保留原件；无可用工具且影响任务时才请用户提供可读版本。
- 用户直接给出文本：以给定文本为准，无需另造文件格式转换流程。

遇到乱码或缺页，先尝试修正提取。无法恢复时指出具体缺失，不编造、不宣称完整。涉及版式识别时使用当前环境可用的文档、PDF 或幻灯片工具；无需预设固定技术栈。

## 整合与对应

在内部把原句或独立信息单元与输出位置对应起来，允许多句合并但每项信息都有去处。保持定义、否定、数量、适用条件、时序和来源绑定；段落衔接只能表达原文支持的关系。原文疑似有错时与概括区分说明，不自行改成另一事实。

保留章节编号、图表标识、公式、代码及引用。表格逐格对应，不为压缩删除字段；图中承载的信息须可读或准确转述。必要的附录、脚注和参考文献属于原文范围，不能混成内部审计附录。

在主技能同次复核中，对最终文本检查提取完整性、信息映射、数字和术语、逻辑关系、乱码与格式。信息对应是语义核对，不靠句数相同证明覆盖；语言修改后重新核对受影响映射。

## Markdown 交付

用户要求文件时保存为指定文件名，未指定时使用 `原文件名_概括整合.md`。标题、段落、列表和表格沿用原文组织；PPT 保留幻灯片顺序及必要页标识。长文才添加目录。可简短标注来源与采用级别，不输出句数、覆盖率、核验报告或审计附件。

用户只要粘贴文本时直接返回 Markdown；不能以生成统计文件替代所需内容。
