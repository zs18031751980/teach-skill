# 数据分析讲解的针对性指导

按主技能确定范围。先分清用户要理解指标、解释结果、掌握分析方法，还是执行完整分析；不把一个指标问答扩展成建模工程。

## 用数据口径连接问题与结论

讲清一行代表什么、统计单位是什么、时间窗和筛选范围是什么，以及指标的分子与分母。必要时解释重复记录、缺失值、异常值及连接操作怎样改变结果，不能只逐句翻译工具调用。

例如两组成功数/总数分别为 1/2 与 90/100，合并成功率是 91/102，不能直接平均两组百分比。若分析目标是给两组相同权重，则简单平均对应另一种口径，应先明确目标。用小表展示分母和汇总过程，比只背“加权平均”更有帮助。

## 方法选择与解释

从问题选择描述、比较、关系分析、预测或因果推断，再说明所用方法的条件及为何合适。没有真实数据时可用明确标注的演示数据，不冒充分析发现。

区分观察结果、统计推断和可能解释。讲统计检验时联系效应大小、样本量、区间与前提，不把统计显著等同于实际重要；讲相关性时不自动给因果结论。图表说明轴、单位、分组、聚合方式和不确定性，不用装饰图替代推理。

若使用预测模型，解释评估数据如何代表实际使用场景。根据任务处理时间顺序或同一对象跨集合的问题；预处理参数只能从相应训练部分学习，不能用测试数据帮助训练。在交叉验证中也要在各训练折内拟合，不能先全数据拟合再分折。[scikit-learn 数据泄漏说明](https://scikit-learn.org/stable/common_pitfalls.html)

## 让代码输出回到问题

解释关键数据变换前后的行数、字段、粒度或分布变化，尤其是分组、连接、过滤和聚合。中间结果只展示理解所需部分，不倾倒整份数据。说明结果支持什么、不支持什么，以及适用范围。

按当前问题在同次内部复核中核对指标口径、变换语义、数据泄漏和结论强度。用户只要文件概括时，原文范围优先，不按本指南自行新增分析或实验。

## 从分析环节选择讲解重点

| 环节 | 需要解释的决策或语义 | 适合展示的证据 | 常见误导 |
|------|----------------------|----------------|----------|
| 明确问题 | 要描述现状、比较群体、预测未来，还是判断干预影响 | 目标量、观察单位与时间范围 | 用同一种建模流程回答所有问题 |
| 读取与类型 | 日期、编码、类别、金额、单位怎样影响后续运算 | 原值与解析结果的少量对照 | 编号被当连续数值；日期格式或单位悄然改变 |
| 缺失与异常 | 值为什么可能缺失、是否代表零、删除或填补影响谁 | 缺失分组和处理前后变化 | 一律填零、按比例机械删列，或把极端真实值当错误 |
| 去重与连接 | 什么构成同一记录、连接键是否唯一、匹配基数是什么 | 连接前后的键及行数 | 结果行数增多就去重，掩盖一对多或多对多关系 |
| 聚合与窗口 | 按谁、按什么时间粒度汇总；窗口边界包含什么 | 分组明细与聚合结果对应 | 对分组均值再简单求均值；滚动计算使用未来信息 |
| 探索与图表 | 分布、分组差异或趋势是否受尺度与样本构成影响 | 保留单位、分组样本量的图或小表 | 截断坐标夸大差异，过度平滑掩盖变化 |
| 统计推断 | 估计对象、抽样或建模前提、区间和检验含义 | 点估计、适当的不确定性及实际影响 | 将 p 值解释成原假设为真的概率，或将不显著等同于没有差异 |
| 预测评估 | 何时获得特征、如何划分数据、指标是否对应使用成本 | 基准方案、验证方案及相关误差 | 用测试集选择方案后仍把它当独立最终评价 |
| 结论沟通 | 数据支持哪项判断、适用于谁、剩余解释有哪些 | 回答原问题的具体数值和限定 | 从单次观测推广到所有人群，或从预测准确直接推出因果 |

## 讲清变换，而不只讲工具语法

以连接为例：订单表同一用户有两行，活动表该用户有三行，按用户做全部匹配时会出现六个组合。这未必是工具错误，但若直接累加订单金额，可能把一笔订单计入多次。应解释目标粒度，再决定是否先聚合、增加连接键或保留明细；不能靠随意删除重复行修复口径。[pandas 连接基数与验证说明](https://pandas.pydata.org/docs/user_guide/merging.html)

以缺失处理为例：未填写消费金额不同于消费金额为零。没有来源依据时先辨明记录含义；若用填补示范，应说明它是演示策略、哪些关系会受影响，而不是保证填补后“数据质量更高”。

## 指标比较与模型解释

分类任务先解释真正关心的是漏报、误报、排序还是概率质量，再选择对应指标；不要只报准确率。回归任务说明误差单位、异常大误差的影响以及平均指标是否掩盖群体差异。用户只问一个指标时，围绕其计算、含义和局限展开，不自动列所有指标。

系数、特征重要性和预测归因需要说明各自回答的问题与所依赖模型，不能互相代替，更不能直接当作改变某变量会造成多少效果的因果证据。

## 结果表达的具体落点

比较“方案更好”时，说明改善了哪个指标、相对哪个基准、在什么样本或时段观察到；解释“可能原因”时区分证据和假设。下一步分析只有确实服务于当前问题时才建议，不凭空补实验结果。

用户看不懂图时先定位坐标、聚合和对照关系；用户不理解代码时解释变换前后数据含义；用户质疑结论时回到口径、样本和推断条件。不要对所有追问都重新执行完整分析流程。
